# ResearchFlow Python Backend

## 1. 适用条件 / When to use

在以下情况使用：

- 实现或评审 ResearchFlow 的 Python 后端模块、FastAPI 端点、Pydantic v2 模型、SQLite 持久化、配置或内部服务。
- 需要判断代码是否符合项目解释器、依赖、类型、日志、安全和测试约束。
- 需要为 T0/T1 后端功能编写实现计划或代码审查意见。

不用于：在没有批准的情况下安装依赖、创建 `.venv`、执行任意用户代码或接入 LLM。

## 2. 输入与前置检查

1. 已确认当前阶段和批准范围；G0 前不写业务代码。
2. 已确认 Python 基线：`C:\Users\Administrator\AppData\Roaming\uv\python\cpython-3.11.16-windows-x86_64-none\python.exe`（3.11.16, 64-bit）。
3. 已确认依赖策略：项目锁定版本；当前仓库尚未建立 `.venv`，也未锁定依赖。未经批准不得安装或升级。
4. 已确认契约与错误码来源；未冻结的 Schema 只能按建议稿实现，并标注待冻结。
5. 已确认测试命令、日志路径和可写目录。
6. 已确认不会读取或写入密钥、私钥、`.credentials.yaml`。

禁止使用 PATH 上的 `python`（3.12）或 `py -3.11`（32 位 3.11.0）。

## 3. 执行步骤

1. **只读探索**：阅读现有模块、契约、测试和配置；确认哪些已实现、哪些为空。
2. **写实现计划**：文件清单、接口、数据流、错误处理、迁移、测试、回滚。
3. **设计类型与边界**：为公共函数和 API 写类型注解；在入口校验输入；明确空值、超限、格式错误。
4. **实现最小变更**：只改批准范围内的文件；复用现有模式，不引入不必要框架。
5. **处理持久化**：SQLite 使用 WAL、显式事务、参数化查询；迁移有版本；不在读路径隐式建表。
6. **处理子进程**：设置超时、资源限制、独立工作目录、退出码与 stderr 捕获；禁止 shell 拼接不可信输入。
7. **处理配置与秘密**：配置与秘密分离；秘密只从正式凭据或环境注入；日志脱敏。
8. **写结构化日志与异常**：明确异常类型、错误码、关联 ID；不吞异常，不用宽泛 `except Exception` 掩盖。
9. **写测试**：单元、边界、负例、集成；使用项目 Python 绝对路径运行。
10. **运行检查**：类型/静态检查、单测、集成测试；记录命令、退出码、日志路径。
11. **更新文档与状态**：只在真实通过后更新实现状态；未测项保持未测。

## 4. 不可违反的约束

- 只使用 Python 3.11.16（64 位）绝对路径或由它创建的 `.venv`；不得用 PATH 默认解释器。
- 不随意升级依赖；依赖变化必须有批准、锁文件和影响说明。
- 不执行任意用户代码；不运行期安装依赖；不默认开放网络。
- 不把密钥、令牌、私钥写入代码、日志、测试或证据包。
- 不绕过后端校验信任前端输入；不在 API 层直接写运行时状态。
- 不在子进程调用中省略超时、资源限制、工作目录隔离和退出码处理。
- 不为了“工程感”引入不必要框架、抽象或依赖。
- 无模型模式必须保留关键规则回退路径；不得把 LLM 输出当成唯一判定。
- 不修改 expected result、测试样本或阈值来掩盖实现错误。

## 5. 输出要求

至少交付：

1. **实现说明**：目标、范围、关键设计决策。
2. **文件变更**：新增/修改/删除的文件及理由。
3. **依赖变化**：无变化时明确写“无”；有变化时列版本、锁文件和批准记录。
4. **测试结果**：命令、解释器绝对路径、退出码、测试数、失败数、日志路径。
5. **风险**：未覆盖路径、性能/资源、兼容性、安全边界。
6. **未完成项**：明确标“未实现/未测/待核实”，不写成完成。

## 6. 验收标准

- 使用的是 Python 3.11.16（64 位）绝对路径或同等 `.venv`。
- 类型/静态检查（如项目已配置）、单测、集成测试通过；失败数为 0 或有明确豁免。
- 没有秘密泄漏；日志不含凭据。
- API、Schema、错误码和审计日志一致。
- 子进程有超时、资源限制、工作目录隔离和退出码处理。
- 没有突破已批准范围；未新增未批准依赖。
- 无模型回退路径存在且有测试，或明确标注未实现。

## 8. 失败与暂停条件

- 解释器不是 3.11.16（64 位），或用户要求使用 PATH 默认解释器。
- 依赖未锁定、需要安装/升级但未获批准。
- 实现需要改冻结 Schema、状态机、安全边界或跨模块接口但未获批准。
- 测试失败且原因未定位；或有人要求修改 expected result/阈值。
- 发现秘密泄漏、越权写入或任意代码执行风险。
- 需要网络、系统配置、权限变更但未获批准。

暂停时报告：失败命令与退出码、受影响文件、风险、需要用户决定的最小问题。
