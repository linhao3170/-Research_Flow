# 证据与信任边界参考

> 规范性来源：`AGENTS.md`、`docs/memory/architecture-decisions.md` 与冻结后的证据契约。
> 本文件是检查清单，不是已冻结字段表。

## 1. 证据等级

| 等级 | 来源 | 能否覆盖执行类必检项 | 说明 |
|---|---|---|---|
| E0 | Agent/LLM 声明 | 否 | 只是待核查主张 |
| E1 | 工具调用、Harness 轨迹、检索 | 否（单独） | 默认 E1，不等于真实执行 |
| E2 | 受控 Executor 的进程/产物观测 | 是 | 需 Collector 记录与信任边界 |
| E3 | 独立 Verifier 的验证证据 | 是（最高） | 关键指标需 L3 覆盖 |

## 2. 角色与权限

| 角色 | 读 | 写 | 签 | 备注 |
|---|---|---|---|---|
| Agent/LLM | 任务、有限状态 | 不得写状态/证据/凭证 | 否 | 经 Tool Gateway |
| Executor | 任务/输入 | 只写工作目录产物 | 否 | 只执行，不裁决 |
| Collector | 执行事件 | 追加 E0/E1/E2 | 否 | 单写者 |
| Gate | 证据/规则 | 只写判定结果 | 否 | 只读证据 |
| Verifier | 证据/原始数据 | 写报告（独立目录） | 可签 | 与 Executor 分离 |
| 外部验签者 | 证据包 + 信任锚 | 否 | 验签 | 不依赖 DB/模型 |

## 3. Gate 检查顺序

1. Schema / 版本校验。
2. 事件顺序与哈希链校验。
3. 产物哈希与生产者校验。
4. 必检覆盖矩阵。
5. 未解释冲突拒绝。
6. 执行类必检项要求 E2/E3。
7. 指标来源节点要求 L3/IRC。
8. 全部通过才 PASS，否则输出 GAP。

## 4. 证据记录规则

- Collector 单写者；追加式；`event_seq` 单调。
- 纠错追加新事件，不原位覆盖。
- 每条记录含证据等级、生产者、时间、关联 ID、哈希、来源。
- E2 至少含 PID/attempt、退出码、stdout/stderr 摘要、耗时、资源峰值、产物 SHA-256、环境指纹（按冻结契约）。
- 不得把 Harness 轨迹直接标 E2。

## 5. 签名与离线验签

- Ed25519、JCS、Merkle 按标准实现；不自创算法/编码。
- 签名载荷覆盖规则版本、证据根、状态等关键字段。
- 私钥不出现在 Git、日志、证据包、前端。
- `verify_bundle.py` 独立于数据库和模型。
- 使用外部可信指纹/信任锚，不只信任包内公钥。
- 哈希链只证明“可发现篡改”，不证明绝对不可篡改。
- k 次 bit-exact 只是限定条件下的经验资格。

## 6. 威胁与负例

| 威胁 | 负例测试 | 预期 |
|---|---|---|
| E0 推动完成 | 只提交 Agent 声明 | Gate 拒绝，状态不变 |
| E1 冒充 E2 | 用 Harness 日志覆盖执行必检 | 拒绝 |
| 缺失必检 | 删除一项 RequiredCheck | GAP，不 PASS |
| 篡改证据 | 改产物/字段/哈希链 | 验签/校验失败 |
| 越权写入 | Agent 直接写 Evidence/DB | 权限拒绝 |
| 复用 Executor 状态 | Verifier 读同进程缓存 | 拒绝或判为不独立 |
| 假 L3 | 复用缓存/摘要 | 拒绝 |
| 信任锚替换 | 用包内公钥验签 | 拒绝 |
| 重放 | 重复 event_seq/旧签名 | 拒绝 |

## 7. 数据最小化

- 公开/合成数据优先。
- 敏感资料先脱敏；只收集必要字段。
- 明确保留期与删除策略。
- 日志、证据包、错误响应均不得泄漏秘密。
