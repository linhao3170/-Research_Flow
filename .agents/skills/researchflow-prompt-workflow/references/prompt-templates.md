# 提示词模板

> 使用方式：按任务选择模板，替换 `<...>`；保留“禁止事项、测试、证据、停止条件”。
> 所有模板默认不 commit、不装依赖、不改冻结契约。

## 1. 通用实现任务

```text
【背景】
项目：ResearchFlow
当前阶段：<phase>
事实来源：<AGENTS.md / docs/... / 用户指令>
现状：<已核实事实>

【目标】
<一句话，可观察的最终结果>

【范围】
允许修改：<路径>
只读：<路径>
禁止修改：<路径>

【禁止事项】
- 不 commit、不建 .venv、不装依赖（除非明确批准）
- 不改 expected result / 测试样本 / 验收阈值
- 不绕过 Gate / Verifier / StateMachine
- 不读取密钥、凭据、私钥

【前置条件】
- 解释器：<3.11.16 绝对路径>
- 分支/状态：<...>
- 审批：<已批准的范围>

【执行步骤】
1. 只读探索并报告事实
2. 给出计划、文件清单、接口/数据流变化
3. 等待批准（多文件/跨模块时）
4. 实施最小变更
5. 运行测试并保存日志
6. 更新状态/文档（如批准）

【测试与证据】
命令：<...>
预期：<exit code / 测试数 / 关键输出>
日志：<路径>

【交付格式】
- 变更摘要
- 文件清单
- 测试命令、退出码、日志路径
- 风险与未完成项

【停止条件】
- 发现需要跨模块/Schema/状态机/安全边界变更
- 测试失败且原因不明
- 需要安装依赖、联网、改系统配置
- 事实与文档冲突
```

## 2. 只读代码审查

```text
【任务】只读审查 <范围>，不修改任何文件。
【事实来源】<文件/提交/日志>
【检查项】
- 是否符合 AGENTS 与冻结契约
- 状态迁移是否只经 StateMachine
- 证据等级/权限边界是否正确
- 错误处理、超时、资源限制
- 测试是否覆盖正例/负例/边界
【输出】按严重度列问题：文件:行、问题、证据、建议；无问题也要说明未覆盖项。
【禁止】不写文件、不运行有副作用的命令、不 commit。
```

## 3. 调试任务

```text
【现象】<可复现描述>
【复现命令】<...>
【期望】<...>
【实际】<退出码/日志/差异>
【范围】只读定位，先不改代码。
【要求】
1. 复现并保存原始输出
2. 列出候选原因及证据
3. 给出最小修复方案与回归测试
4. 等待批准后实施
【停止】无法复现、需要改测试预期、需要外部服务/凭据。
```

## 4. 调研任务

```text
【问题】<需要回答的具体问题>
【来源】优先项目文档；外部资料标注 URL 与访问日期
【范围】只读；不安装、不联网写入、不改项目文件
【输出】
- 结论与置信度
- 证据链接/文件:行
- 反例/冲突
- 未核实项
【禁止】不把搜索摘要当事实；不编造引用。
```

## 5. 子 Agent 只读审查

```text
【角色】只读审查者，无写入权、无决策权。
【范围】<文件/目录/提交>
【任务】检查 <具体清单>，输出问题与证据。
【约束】
- 不修改任何文件
- 不运行有副作用的命令
- 不 commit、不装依赖
- 不把推测写成事实
【输出格式】
| 严重度 | 文件:行 | 问题 | 证据 | 建议 |
【停止】范围不清、需要写入、发现敏感信息。
```

## 6. 阶段验收任务

```text
【阶段】<阶段号/门禁>
【验收项】逐条列出
【证据要求】每项：命令、解释器、退出码、日志路径、时间
【禁止】不提前标 PASS；不编造测试；不修改阈值
【输出】验收矩阵 + 未完成项 + 风险
【停止】关键证据缺失或测试失败。
```
