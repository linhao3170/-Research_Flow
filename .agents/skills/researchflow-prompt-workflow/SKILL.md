# ResearchFlow Prompt Workflow

## 1. 适用条件 / When to use

在以下情况使用：

- 需要把自然语言目标转成可执行、可验收的任务提示词。
- 需要给子 Agent 分配边界明确的只读审查、调研或验证任务。
- 需要编排多阶段实施、调试、评审或实验操作。
- 需要把“继续做”“完善一下”这类模糊指令拆成有停止条件的任务。

不用于：代替需求评审、替用户做架构决策、生成诱导 Agent 编造结果的提示词。

## 2. 输入与前置检查

1. 目标、事实来源、目标文件/目录、允许的写入范围已明确。
2. 已确认当前阶段、已批准范围和禁止事项。
3. 已判断任务风险：只读 / 可写 / 需要审批 / 禁止执行。
4. 已确认验证方式：命令、测试、日志、证据路径。
5. 若任务跨多个文件或模块，先要求计划和 diff，不直接给“全部改完”的指令。

缺少目标、范围、验收条件或停止条件时，先补全，不生成执行提示词。

## 3. 执行步骤

1. **写背景**：项目、当前阶段、为什么要做、相关事实来源。
2. **写目标**：一句话说明可观察的最终结果，不用“优化”“完善”等无法判断的词。
3. **写事实来源**：必须读取的文件、字段、命令；区分“已核实”与“待核实”。
4. **写范围**：允许修改的路径、禁止修改的路径、只读区域。
5. **写禁止事项**：不得 commit、不得装依赖、不得改测试预期、不得绕过质量门、不得读密钥等。
6. **写前置条件**：解释器、分支、状态、依赖、审批是否就绪。
7. **写执行步骤**：按顺序编号；多文件任务要求先输出计划和 diff 计划。
8. **写测试与证据**：真实命令、预期退出码、日志路径、需要保留的原始输出。
9. **写交付格式**：文件清单、变更摘要、测试结果、风险、待确认事项。
10. **写停止条件**：遇到什么情况必须停下来问用户，而不是自行扩大范围。
11. **做自检**：提示词是否可判断“开始条件、完成条件、停止条件”；是否存在诱导编造或绕过门禁的语言。

详细模板见 `references/prompt-templates.md`。

## 4. 不可违反的约束

- 每条提示词必须包含：背景、目标、事实来源、范围、禁止事项、前置条件、执行步骤、测试、证据、交付格式、停止条件。
- 必须明确只读/可写、是否需要审批、允许修改的路径。
- 多文件任务先要求计划和 diff，再等待批准。
- 子 Agent 只负责边界明确的只读审查或调研；主 Agent 保留决策、写入和最终验收责任。
- 每条命令说明用途和预期结果，不堆砌无法解释的命令。
- 禁止“全部做好”“尽可能完善”“随便优化”等不可验收指令。
- 不允许提示词诱导 Agent 编造测试、伪造日志、修改 expected result 或绕过质量门。
- 不得把尚未批准的范围写进任务；不得把“计划”写成“已完成”。

## 5. 输出要求

交付一份可直接复制的提示词包，至少包含：

1. **任务提示词**：按上述字段组织，中文，路径使用绝对路径或明确相对路径。
2. **执行顺序**：多阶段任务的阶段划分与依赖。
3. **审批点**：哪些步骤前必须等待用户确认。
4. **验收清单**：可逐项打勾的检查项。
5. **停止条件**：遇到冲突、失败、越界、缺证据时的处理。
6. **子 Agent 边界**（如适用）：只读范围、输出格式、不得执行的写操作。

## 6. 验收标准

- 每个任务都能判断开始条件、完成条件和停止条件。
- 提示词中的事实来源可定位到文件/字段/命令。
- 写入范围明确，审批点明确，禁止事项明确。
- 测试与证据要求真实可执行，不依赖 Agent 自述。
- 子 Agent 任务没有写入权或决策权，除非用户明确授权。
- 没有模糊、不可验收或诱导造假的表述。

## 8. 失败与暂停条件

- 目标无法转成可观察结果。
- 允许修改的路径或审批状态不明确。
- 任务需要跨模块、改 Schema、改状态机或安全边界，但未获批准。
- 验证命令不可执行，或预期结果无法定义。
- 用户要求跳过测试、伪造证据或绕过质量门。
- 子 Agent 任务需要写入权，但用户只批准了只读审查。

暂停时输出：缺失信息、风险、需要用户确认的最小问题集；不生成“先做再说”的提示词。
