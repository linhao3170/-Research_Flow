# ResearchFlow Spec-Driven Development

## 1. 适用条件 / When to use

在以下情况使用：

- 把用户需求、策划书条款或赛事要求转成 PRD、用户故事、实施计划、验收条件。
- 需要判断某需求是否属于 T0/T1/T2，是否已有来源、优先级和验收证据。
- 需要修改已冻结的规格、接口、Schema、状态机或安全边界。
- 需要先做只读探索，再给出多文件实施方案。

不用于：直接写业务代码、直接改冻结契约、用自然语言宣称需求已完成。

## 2. 输入与前置检查

1. 已加载项目 `AGENTS.md`，并已按 `researchflow-onboarding` 读取当前阶段与阻塞。
2. 需求有明确来源：用户书面指令、策划书章节、已批准 ADR/PRD、正式外部资料。聊天中的临时想法只能标为“候选需求”。
3. 已确认需求编号规则：项目使用 `FR-001` 至 `FR-020`。当前 PRD 尚未建立，具体条目内容**待核实**，不得凭编号臆造需求。
4. 检查是否触及需审批边界：跨模块、Schema、数据库、状态机、安全边界、冻结架构。
5. 检查目标阶段：G0 前只整理规格，不写业务代码；T0 不接入 LLM 或六个 Agent。

若需求来源、优先级或目标阶段不明确，先列问题清单，不进入实施计划。

## 3. 执行步骤

1. **复述目标与边界**：用一段话说明要解决的问题、目标用户、成功标准、明确不做什么。
2. **建立需求追踪表**：每条需求记录 ID、来源、原文摘要、优先级、所属模块、依赖、风险、验收证据、状态。详细字段见 `references/requirement-traceability.md`。
3. **映射到 FR 编号**：只映射已有来源的条目；没有来源的编号留空并标“待定义”，不要为了凑满 FR-001–FR-020 编造内容。
4. **写用户故事与验收条件**：采用“作为…我希望…以便…”结构；验收条件必须可观察、可测试，包含正例、负例和边界。
5. **检查非功能需求**：性能、资源上限（Windows 11 / 16GB / CPU-only / 并发上限 2）、安全、审计、离线、可复现、数据最小化。
6. **做只读探索**：读取现有目录、契约、测试与状态；确认哪些是已实现、哪些只是计划。不得把空目录当成已实现。
7. **给出实施方案**：文件清单、接口/数据流变化、迁移影响、测试计划、回滚方案、审批点。多文件任务先交计划和 diff 计划，等待批准后再改。
8. **标注范围外事项**：把 T1/T2 功能、LLM/Agent、Harness Adapter 等非当前阶段内容明确列为“不做/后续”。
9. **更新追踪表状态**：只有真实实现和测试证据齐全时才可标为已完成；否则保持计划/进行中/待核实。

## 4. 不可违反的约束

- 不得擅自修改策划书核心目标、第一版范围或已冻结架构。
- 不得把 T1/T2 功能提前放入 T0。
- 不得把 Agent 的自然语言声明设计成可信完成证据。
- 不得用“全部做好”“尽可能完善”等不可验收表述。
- 不得绕过 Gate、Verifier、StateMachine 或权限边界来简化规格。
- 不得在 G0 前写业务代码；不得用规格文档冒充实现。
- 跨模块、Schema、数据库、状态机、安全边界或冻结架构变更，必须先获得用户明确批准并记录 ADR。
- 不得编造来源、优先级、FR 内容或验收数据。

## 5. 输出要求

至少交付：

1. **需求追踪表**：ID、来源、需求摘要、优先级、模块、依赖、风险、验收证据、状态。
2. **用户故事与验收条件**：每条含正例、负例、边界。
3. **实施计划**：文件清单、接口、数据流、迁移、测试、回滚、审批点。
4. **范围声明**：本期做 / 不做 / 待确认。
5. **风险与依赖**：技术、数据、权限、外部依赖。
6. **变更建议**：若触及冻结规格，给出变更理由、影响面和需批准的 diff 计划。

## 6. 验收标准

- 每条需求都有来源和至少一个可验证条件。
- FR 映射没有无来源条目；未定义条目明确标“待定义”。
- 范围外事项明确标记，未混入本期交付。
- 实施计划能判断开始条件、完成条件和停止条件。
- 需要审批的变更没有被写成“已决定”。
- 没有修改任何冻结文件或业务代码，除非用户已批准且记录在案。

## 8. 失败与暂停条件

- 需求来源无法核实，或用户口头描述与书面资料冲突。
- FR-001–FR-020 的正式定义尚未建立，却要求给出“完整需求合同”。
- 需求触及冻结架构、Schema、数据库、状态机或安全边界，未获批准。
- 目标阶段不明确，无法判断是否属于 T0/T1/T2。
- 验收条件无法观察或无法由测试/证据支撑。
- 需要修改策划书核心目标或扩大第一版范围。

暂停时输出：冲突点、涉及文件/章节、可选方案、需要用户决定的问题；不自行选择。
