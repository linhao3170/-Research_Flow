| 标准 | 判定 |

| 失效传播 | 上游变化使后代 `INVALIDATED`，计划冻结，保守重跑，stale 证据被 Gate 拒绝 |

## 3. T0 主场景

### 3.1 正常路径（一条内置表格 ML 任务）

| 步骤 | 用户动作 | 系统响应 | 可观察证据 |
|---|---|---|---|
| 1 | 提交任务 | 校验通过，返回任务标识与 `CREATED` | `fr-001/positive.json` |
| 2 | 触发建图 | DAG 校验通过，返回 `graph_version` 与拓扑序 | `fr-002/graph_version.json` |
| 3 | 开始执行 | 状态经 `PLANNING → READY → RUNNING`，写审计 | `fr-003/audit_log.jsonl` |
| 4 | 模板执行 | 独立目录子进程执行，记录退出码/产物哈希/资源峰值 | `fr-004/artifact_hashes.json` |
| 5 | 采集证据 | E0/E1/E2 追加，`event_seq` 单调，链哈希生成 | `fr-005/event_seq.jsonl` |
| 6 | 门控评估 | 覆盖矩阵生成；全部必检满足则 PASS | `fr-006/coverage_matrix.json` |
| 7 | L1/L2 | 过程完整性与结果自洽通过 | `fr-007/l1.json`、`l2.json` |
| 8 | L3 | 新目录、独立进程真实重训/推理 | `fr-007/l3/retrain.log` |
| 9 | 签发 | `VERIFIED` 报告 + 证书；两者含 `schema_version`/`issued_at`，签名载荷含 `schema_version`、规则版本/证据根/状态 | `fr-008/certificate.json` |
| 10 | 导出 | Evidence Bundle 生成 | `fr-009/` 包目录 |
| 11 | 离线验签 | 独立环境 + 外部可信指纹验签通过 | `g6-t0/true_bundle.verify.log` |

### 3.2 失效路径（WP-R）

| 步骤 | 触发 | 系统响应 | 可观察证据 |
|---|---|---|---|
| 1 | 上游输入/参数/代码/环境/规则变化 | 计算受影响后代并标记 `INVALIDATED` | `fr-010/invalidated.jsonl` |
| 2 | 生成恢复计划 | 计划含受影响节点、原因、计划哈希；执行前冻结 | `fr-010/recovery_plan.json` |
| 3 | 保守重跑 | 受影响后代全部重跑；不签 DC、不做 SPA | `fr-010/rerun_attempts.jsonl` |
| 4 | 重新门控 | stale 证据被拒绝；新证据通过才继续 | `fr-010/stale_reject.log` |

### 3.3 拒绝路径（负例）

| 场景 | 期望 | 不得出现 |
|---|---|---|
| 只有 E0 声明 | 执行类必检项不通过 | 状态推进到 `VERIFIED` |
| 缺 E2/E3 | Gate 输出 `GAP` | 报告 `VERIFIED` |
| 假 L3（只重算指标） | 判定为未达 L3，拒绝 | 记为 L3 通过 |
| 篡改证据 payload | 链/哈希校验失败 | 验签通过 |
| 非 `VERIFIED` 报告 | 不签发凭证 | 生成 `CompletionCertificate` |
| 只信包内公钥 | 验签拒绝 | 判定真包通过 |
