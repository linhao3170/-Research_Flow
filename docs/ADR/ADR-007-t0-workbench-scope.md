## 1. 背景

`OQ-027` 记录：T0 的“最小工作台”在策划书里没有页面级定义，只要求任务、DAG、证据、报告可见。若不在 G0 锁定范围，容易在实现期扩张为 T1 的六页工作台，拖慢 T0 出口。

## 2. 决策（2026-11-15 批准）

1. T0 工作台固定四视图：任务列表/详情、DAG 视图、证据视图、报告视图。
2. 四视图**只读**：不写状态、不写证据、不触发恢复；恢复只能由内部路径触发（见 `ADR-004`/`ADR-006`）。
3. 不实现六页工作台、角色面板、知识库、Bench 面板。
4. 若需新增页面或写入型交互，先改本 ADR 并获用户批准，不得以“顺手加一个按钮”的方式扩范围。

## 3. 三个边界的最终选择

| # | 问题 | 选项 | **最终裁决** |
|---|---|---|---|
| 1 | 四视图的接口边界（是否暴露证据分页、报告下载） | (a) 只读当前页所需；(b) 暴露分页与下载 | **(a)**：证据固定 `GET /evidence?limit=200` 单页；T0 无分页交互、无报告/凭证文件下载；只读展示报告/凭证 JSON |
| 2 | 工作台与 API 是否同进程 | (a) 同进程只读；(b) 独立只读服务 | **(b)**：独立 Streamlit 进程，只发 GET；不 import 持久层/StateMachine/Collector；API 不可达时显式报错 |
| 3 | “证据视图”是否展示 stale 标记与失效原因 | (a) 展示；(b) 只展示有效证据 | **标记按 (a)，原因暂不展示**：展示 `STALE` 与失效计数；`GET /evidence` 当前不返回 `reason_code`/`cause_type`/`cause_ref`，原因展示需先改冻结 REST 契约并另立方案 |

## 4. 批准后的后果（已生效）

- ⑦ `WP-13` 的交付与验收按四视图固定；截图与 walkthrough 作为证据。
- 任何新增页面都需新 ADR。

- 分页、报告下载、失效原因展示均不在本次批准范围；如需要，先改契约/ADR。
