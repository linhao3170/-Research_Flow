# ADR-006：T0 API 面与回环免认证 + 启动守卫

| 字段 | 内容 |
|---|---|
| 编号 | `ADR-006` |
| 状态 | **ACCEPTED**（用户 2026-11-09，决议 8） |
| 日期 | 2026-11-09 |
| 决策者 | 用户（书面决议 8） |
| 影响版本 | REST API `1.0`（T0 面）；启动流程 |
| 取代 | 无 |

## 1. 背景

T0 是 Windows 11 单机、CPU-only、无用户体系的最小可信闭环。两个问题必须先定：

1. `/api/v1/tasks/{id}/recover` 若开放给外部调用，T0 没有完整的恢复状态机与审批语义（见 `ADR-004`），任何人都能触发重跑，范围与语义都不清楚。
2. 单机场景默认免认证最省事，但一旦误配置绑定到非回环地址，端口就暴露给局域网，且没有 token 兜底。

## 2. 决策

1. **T0 不注册 `POST /api/v1/tasks/{id}/recover`**：访问返回 `404 Not Found`，不得返回 405/403，也不得用空实现接受请求。T0 的失效只由输入/图版本变化内部触发。
2. 默认且仅允许回环绑定：`127.0.0.1`、`::1`、`localhost`。
3. 回环 + 单机场景**允许无认证**；该口径登记为**已接受风险**，不得表述为“已安全加固”。
4. **启动守卫**：配置的绑定地址非回环且未配置访问 token 时，拒绝启动——不监听端口、退出码非 0、写一条不含 token 的启动审计；失败信息只说“non-loopback bind requires token”，不回显配置值。
5. 负例测试必须断言：`bind=0.0.0.0` 且无 token → 进程非 0 退出、端口未监听、无任务创建。

## 3. 后果

- ⑥ §4.1 的 T0 端点清单移除 `/recover`；§4.6 增加认证与启动守卫表。
- ⑦ 测试矩阵新增 `T0-CT-API-404-*` 与 `T0-SEC-BIND-*`。
- T0 不实现用户体系、TLS、反向代理鉴权；这些属 T1/T2。
- 已接受风险必须在 G0 冻结时由用户签字确认，不得在对外材料中省略。

## 4. 备选（未选）

| 方案 | 未选原因 |
|---|---|
| T0 开放 `/recover` 并返回 409 | 外部触发语义未定义，且会绕过 `ADR-004` 的内部触发边界 |
| 始终要求 token | 单机本地开发成本高，且 T0 无密钥分发机制，容易写成硬编码密钥 |
| 允许 `0.0.0.0` 默认绑定 | 直接暴露端口，且无认证；违反最小暴露原则 |
| 只在文档里写“仅回环”，不加启动守卫 | 依赖人工配置正确，误配置时无兜底 |

## 5. 验证

- `tests/t0/test_fr_001_no_recover*`：断言 404 且无状态变化。
- `tests/t0/test_security_bind*`：断言非回环无 token 时拒绝启动。
