# ADR-005：失败迁移的审计写入语义

| 字段 | 内容 |
|---|---|
| 编号 | `ADR-005` |
| 状态 | **ACCEPTED**（用户 2026-11-09，决议 7） |
| 日期 | 2026-11-09 |

| 影响版本 | StateMachine `1.0`；`audit_log` |
| 取代 | 无（原 v0.1 的 ADR-004 候选编号已顺延） |

## 1. 背景

附录 F.1 要求“迁移失败也写 `audit_log`”，`NFR-05` 要求可审计；但状态迁移与审计若放在同一事务，状态写失败时事务回滚会把审计一起回滚，导致**失败迁移没有记录**。v0.1 把这条记为 `OQ-DB-1`，两种口径无法同时成立。

## 2. 决策

1. **成功迁移**：状态更新与 `audit_log(result=OK)` 在**同一事务**，原子提交。
2. **失败迁移**：状态事务回滚后，**在新事务**写 `audit_log(result=DENIED)`，字段包含 `error_code`、尝试的 `previous_state`/`next_state`、`correlation_id`、`actor`、`reason_code`、`rule_version`。
3. 测试必须证明该 `DENIED` 记录在状态回滚后**仍存在**（真实 SQLite 文件，禁止用 mock 或内存库替身）。
4. 若第二个事务也失败：降级写**结构化 stderr**（单行 JSON，含同样字段 + `audit_write_failed=true`），并在测试报告中计为**测试缺口**；不得静默吞掉，也不得把缺口写成通过。
5. 降级路径本身必须有测试：人为让审计事务失败，断言 stderr 行出现。

## 3. 后果

- `audit_log` 必须只追加，且允许在无状态变更时单独插入。
- `WP-03` 的测试矩阵新增 `T0-UT-SM-DENIED-*`；证据 `denied_survives_rollback.log`、`audit_degraded_stderr.log`。
- 失败迁移的审计不参与状态事务的原子性；读取方必须接受“有 `DENIED` 记录但状态未变”这一合法组合。

## 4. 备选（未选）

| 方案 | 未选原因 |
|---|---|
| 状态与审计同事务（失败也同事务） | 回滚会删掉 `DENIED`，等于“失败无审计”，违反 F.1/NFR-05 |
| 先写审计再写状态 | 审计会为“尚未决定”的操作先记账；且成功路径仍需二次写 |
| 失败时只写日志文件、不写 DB | 无法与状态、任务关联查询，审计链断裂 |
| 二次失败静默 | 证据缺口被隐藏，正是本项目要避免的 |

## 5. 验证

- `tests/t0/test_fr_003_denied*`：真实 SQLite，制造约束冲突使状态写失败，断言回滚后 `DENIED` 存在。
- 人为关闭审计写入（或注入异常），断言 stderr 单行 JSON 出现，且测试报告标记缺口。
- 文档：⑤ §9.7 / `I-14`、⑥ §2。
