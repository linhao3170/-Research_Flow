先完成不调用产品 API 的契约/测试替身和本地机制，再用现有授权凭据做一笔受限冒烟、少量代表任务估价；模型编写这些代码仍消耗开发 API。每次发产品请求前预留最大输出与允许重试的费用，剩余额不足以覆盖最坏请求则不发起；失败和超时按可能已计费保守记账。80% 余额消耗时提示，90% 后只安排已预留的必要验收，100% 禁止新调用。供应商计费单位/时间档/缓存口径未明时不声称可硬限额。

API 预算是使用额度，不授权发送私人数据、开启产品默认外网或改全局配置。数据只用已批准的公开/合成样本和最小摘要；生产工具白名单不随模型能力扩大。付费实验的任务数×方案数×重复数×角色/重试上界先计算，不在正式评测开始后才发现超支。产品预算不足时仅在开发余额充足的前提下完成本地部分并保留实验缺口，不以 mock、缓存回放冒充真实模型结果；开发预算不足则结束新增工作并按前述暂停机制处理。

## RF-Bench 60 与比较协议

冻结任务构成为：正常 12、数据异常 6、代码环境 6、工具资源 4、输出协议 4、结果异常 4、G-dev 8、G-hold 16。重复运行不增加独立任务数。正式盲测运行前，开发者不得读取 hold 的攻击细节；不能由同一个已经参与调参的 Agent 生成 hold 后自称独立盲测。提前泄露或用 hold 结果调规则时，该批转为开发/回归集，保留污染记录，重新由独立构造者封存新 hold；不能沿用其“未见样本”结论。

四方案：A 单 Agent 顺序模板、无内部 EG/动态调度；B 多 Agent 固定 DAG；C 多 Agent 动态调度与恢复、无完整 EG/DC/SPA/VAS；D ResearchFlow。所有最终产物交同一个独立外部评估器，避免只因 D 有验证器就天然判优。

必须集中裁决分期口径：冻结 FR-018 在 T1 要求四方案/消融，但原书 D 是完整机制，而 DC/SPA/VAS 属 T2。提出 T1 使用功能掩码明确的 `D-T1`、T2 另冻结 `D-final` 的方案，经确认后执行。未获裁决不把 D-T1 称完整 D，不自行降低 FR-018/G5 要求。

正式运行前冻结 manifest、任务/攻击脚本哈希、规则、模型版本/温度、prompt 版本、种子、数据/split、token 和 wall-clock、并发/重试、统计脚本、缺失/失败处理及停止规则。正常/一般异常按策划书至少三次重复；统计以任务为单位。先做小规模 dry-run 查脚本缺陷，再封存正式版本；正式结果不得与 dry-run 混合。

T1 消融包含 EG、定向恢复、L2-only 不安全测试基线、逐角色 role-off、R1/R2/R3、权限和离线包复核。关闭保护只能发生在隔离测试构建，不能污染生产配置。DC/SPA/VAS 与 Adapter 实验留在 T2，明示尚未运行。

结果至少报告：完成率、错误放行/拒绝的分子与分母、故障检出、恢复成功/重跑节点/时间、关键 L3 覆盖、资源峰值、模型 token/费用、CPG 与角色作用。CPG 是信息流指标，不等于语义质量。pass@3 与 pass^3 分开按冻结定义计算，不能合并成“成功率”。二值区间、配对比较、bootstrap 和预注册 TOST 按项目基准规范执行，保留失败编号与负面结果。

16 个 G-hold 即使 0 错放也只是有限留出证据，不宣称错误率已低于 5%。收益不显著不意味着可以改 expected、样本、预算或阈值；完成与否取决于实验真实和既有验收条件，效果未达目标则如实写缺口。

完整 G6：由可信外部工具与包外锚验证真包；依次构造修改 payload、替换公钥、删除 split_manifest、修改报告状态、破坏签名五类负例。断言规定错误码/失败环节，不能因为路径缺失或工具崩溃就算拒绝成功。保留包哈希、调用命令、环境与原始输出。

## 审查与持续交接

每包流程：需求/验收→接口和统一命名→伪代码→后端→定向测试/负例→一次只读独立审查→修复复验→状态同步。A 为有证据的正确性、安全、数据/契约和必需验收缺陷，必须修；B 为不影响当前出口的性能/体验改进，排期；C 为偏好或范围外想法，停止扩写。不能把冻结要求降级，也不能无证据把所有建议升 A。相同问题只因新证据或复验失败重新开启。

按需加载九个现有 `researchflow-*` Skill；后端、状态机、证据、契约、测试与记忆分别用对应 Skill。主 Agent 写入，子 Agent 只读审查/查官方资料；共享文件单写。优先使用已接入 Context7 和本地文档，外部查询不外发项目数据；额外插件必须解决明确缺口，列收益/权限/费用/diff 后再申请，不以“装得多”作为完成条件。

测试采用项目 3.11.16/64bit `.venv`，定向测试覆盖新模块，出口真实跑 `-m pytest tests -q -p no:cacheprovider`、契约 validator、自检、state_sync validate/render/check 和文档漂移检查。不得照抄不存在的测试路径。每次记录完整命令、解释器、时间/耗时、退出码、权限策略、日志路径；BLK-003 按当前证据处理，不复用旧 full-access 授权。

更新顺序：状态 JSON→state_sync validate/render/check→追加 CHANGELOG→最新交接置顶。阶段状态只由 JSON 维护；计划文档仅引用任务 ID、决策和下一动作。只把稳定事实写记忆；不得自动 commit 或擅改 last_verified_commit。预算/用量随会话恢复，不能重置。
